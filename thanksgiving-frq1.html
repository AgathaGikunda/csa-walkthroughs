Day 1: Objects and instance methods

Today’s goal: call every method on the right thing, in the right way. FRQ 1 always gives you objects and methods, and most lost points start with a wrong call.

Review in your slides

Unit 1 deck: slides 36–37 (void vs non-void), 52–54 (objects, references, null), 56–59 (constructors and new), 61–62 (calling instance methods, null crash).

Key rules

There are three ways to call a method. Ask: where does this method live?

Where the method livesHow you call itExample
Inside another object the class gives youobject.method(arguments)driverTwo.getDeliveryTime(3)
In the class you are writing (a helper, or your part (a) method)method(arguments), no dotisMinuteFree(period, m)
A class (static) method, like MathClassName.method(arguments)Math.random()
  • Non-void methods give back a value. Store it or use it: double t = driverTwo.getDeliveryTime(i);
  • Void methods just do a job. Never store them: oven.clean();
  • Arguments must match the header. If the header says getDeliveryTime(int order), the call needs one int.
  • Instance variables are the private fields at the top of the class. Use them by name, anywhere in the class.
  • Parameters are in the method header. They only exist inside that method.
  • Preconditions are promises. “Precondition: numBirds > 0” means you never need to check it.

Real mistake From the Recovery Check

int fast1 = 0;
fast1.getDeliveryTime(i)         // ✗ fast1 is an int counter. Numbers have no methods.

int driverOne = 0;               // ✗ reuses the object's name for a counter,
                                 //   so driverOne is no longer the driver

slow.getDeliveryTime(order)      // ✗ there is no object called slow

driverTwo.getDeliveryTime(order) // ✓ the object the question gave you

The fix is always the same: copy the object names from the class information. Give your own variables (counters, totals) different names.

Day 2: Brackets, braces and conditions

Today’s goal: put every bracket in the right place without thinking, and write conditions with &&, || and ! correctly.

Review in your slides

Unit 2 deck: slides 12–17 (if, if-else, nested if, if-else-if), 19–22 (logical operators, short-circuit, equivalent expressions), 32–33 (for loop parts and the order they run). Unit 1 deck: slides 38 and 46 (calls that won’t compile).

Key rules: where things go

WhatRuleExample
Method callAlways (), even when emptys.length(), play()

elseNever takes a conditionelse or else if (x > 5)

Brace check: after writing, put your finger on each { and find its }. Code inside a pair is indented one step. If the indents and the braces disagree, the braces win.

Real mistake From the Recovery Check

{for (int order = 2; order <= numOrders; order++);  // ✗ { before for, and ; ends the loop here
{if (d > most)                                       // ✗ { goes after the ), not before if
} else (a == b) {                                    // ✗ else never has a condition
elif (y > x)                                         // ✗ Java has no elif. Write else if
} if (driverOne.getDeliveryTime(i) > ...)            // ✗ a stray } closes the loop early
driverOne.getDeliveryTime < driverTwo...             // ✗ the call is missing (i)

Compound conditions

OperatorMeansTrue when
a && bandboth are true
a || borat least one is true
!anota is false
  • Ranges need two full comparisons. Write x >= 10 && x <= 20, never 10 <= x <= 20.
  • Each side is a full comparison. Write x == 3 || x == 5, never x == 3 || 5.
  • Short-circuit protects you. In s.length() > 0 && s.substring(0, 1).equals("a"), the substring never runs on an empty String.
  • Not, and, or: !(a && b) is the same as !a || !b. !(a || b) is the same as !a && !b.
  • Booleans need no == true. Write if (oven.isOn(h)).

Day 3: String methods

Today’s goal: use the six Quick Reference String methods without guessing, and loop through a String safely.

Review in your slides

Unit 1 deck: slides 71 (positions start at 0), 72–77 (the six methods, one per slide), 78 (reading a username), 79 (recap). Unit 2 deck: slides 45–48 (one character at a time, and building a new String).

Key rules

All six are on the Java Quick Reference. Keep it open today.

MethodGives backRemember
s.length()intThe last index is length() - 1.
s.substring(a, b)StringFrom a up to, but not including, b. Its length is b − a.

s.substring(6) is highlighted: “giving”. The length is 12, so the last index is 11.

  • One character: s.substring(i, i + 1).
  • Strings never change. name.substring(1); on its own line does nothing. Store it: name = name.substring(1);
  • Crashes: any index below 0 or above length() throws an error. substring(length()) is fine and gives "".

The four loop shapes

// 1. Visit every character
for (int i = 0; i < s.length(); i++)
{
    String ch = s.substring(i, i + 1);
}

// 2. Visit every piece of length k (stop early so i + k never passes the end)
for (int i = 0; i <= s.length() - k; i++)
{
    String piece = s.substring(i, i + k);
}

// 3. Build a new String
String result = "";
for (int i = 0; i < s.length(); i++)
{
    result = s.substring(i, i + 1) + result;   // adds to the front, so this reverses s
}

// 4. Split at a marker
int pos = s.indexOf(",");
String before = s.substring(0, pos);
String after = s.substring(pos + 1);

Worked example: count double letters

countDoubles("bookkeeper") returns 3, for “oo”, “kk” and “ee”.

public int countDoubles(String word)
{
    int count = 0;
    for (int i = 0; i < word.length() - 1; i++)       // stop 1 early: we look at i + 1
    {
        String now = word.substring(i, i + 1);
        String next = word.substring(i + 1, i + 2);
        if (now.equals(next))                         // equals, not ==
        {
            count++;
        }
    }
    return count;
}

Why word.length() - 1? On the last pass, i + 2 must still be at most length(). If the loop went to i < word.length(), the last substring(i + 1, i + 2) would crash.

Day 4: Math.random

Today’s goal: write any random range from memory, and turn a percent chance into an if. Random numbers were the whole of the 2024 FRQ 1.

Review in your slides

Unit 1 deck: slides 48 (the Math methods), 49 (a random number in a range), 50 (int or double), 17–19 (casting and rounding).

Key rules

Math.random() gives a double from 0.0 up to, but never reaching, 1.0.

The recipe for a whole number from low to high, both included:

int howMany = high - low + 1;
int r = (int) (Math.random() * howMany) + low;
You wantExpressionSmallestLargest
A die, 1 to 6(int) (Math.random() * 6) + 116
0 to 9(int) (Math.random() * 10)09
10 to 50(int) (Math.random() * 41) + 101050
−5 to 5(int) (Math.random() * 11) - 5−55

A percent chance is a comparison, not a range:

You wantCode
A coin flipif (Math.random() < 0.5)
A 30% chanceif (Math.random() < 0.3)
20% A, 30% B, 50% Cdouble r = Math.random(); then if (r < 0.2) A, else if (r < 0.5) B, else C

Watch out The four traps

(int) Math.random() * 6 + 1       // ✗ the cast hits Math.random() first, giving 0. Always 1.
(int) (Math.random() * 6)         // ✗ gives 0 to 5. You forgot the + 1.
(int) (Math.random() * 40) + 10   // ✗ gives 10 to 49. howMany is 50 - 10 + 1 = 41.

if (Math.random() < 0.2) { ... }        // ✗ two separate random numbers,
else if (Math.random() < 0.5) { ... }   //   so the chances come out wrong

For the last trap: when one random event decides several outcomes, make one random number, store it, and compare that variable.

The four AP question types

  1. What range? (int) (Math.random() * 8) + 3 gives 3 to 10. Smallest: 0 + 3. Largest: 7 + 3.
  2. Write the expression. 5 to 12: howMany is 12 − 5 + 1 = 8, so (int) (Math.random() * 8) + 5.
  3. Simulate inside a method. Make the random value inside the loop, so each pass gets its own:
    /** Rolls a die until it shows 6. Returns how many rolls it took. */
public int rollsUntilSix()
{
    int rolls = 0;
    int roll = 0;
    while (roll != 6)
    {
        roll = (int) (Math.random() * 6) + 1;
        rolls++;
    }
    return rolls;
}
  4. Which code gives the right chance? Math.random() < 0.25 is true 25% of the time. So is (int) (Math.random() * 4) == 0, because 0 is one of four equally likely values.

Today’s goal: read a question and know which pattern it needs before writing a line. Almost every FRQ 1 part is one of these six, or two combined.

The patterns

#PatternThe question saysMistake to avoid
1Count“how many…”Counter declared inside the loop, so it resets every pass
2Sum and average“total…”, “average…”int / int drops the decimal. Cast first: (double) total / n
3Find the best“which order / day / item had the most…”One variable doing two jobs. You need the best value and where it was.
4Compare two“who won more…”, “which was faster…”> when fewer minutes means faster
5Streak with reset“in a row”, “consecutive”Forgetting count = 0 when the streak breaks
6Search with early return“the first…”, “return −1 if none”return -1 inside the loop, or returning the loop variable after it

The skeletons

1. Count

int count = 0;
for (int i = 1; i <= n; i++)
{
    if ( /* condition */ ) { count++; }
}
return count;

2. Sum and average

int total = 0;
for (int i = 1; i <= n; i++)
{
    total += /* value for i */;
}
return (double) total / n;

3. Find the best

int best = 1;                      // start from a real item...
double most = obj.getValue(1);
for (int i = 2; i <= n; i++)       // ...then check the rest
{
    double v = obj.getValue(i);
    if (v > most)                  // > keeps the earliest in a tie
    {
        most = v;
        best = i;
    }
}
return best;

4. Compare two

int oneWins = 0;
int twoWins = 0;
for (int i = 1; i <= n; i++)
{
    if (a(i) < b(i)) { oneWins++; }          // pick < or > from the question
    else if (b(i) < a(i)) { twoWins++; }     // a tie adds to neither
}
// after the loop: compare oneWins and twoWins, return the right answer

5. Streak with reset

int streak = 0;
for (int i = 1; i <= n; i++)
{
    if ( /* item i is good */ )
    {
        streak++;
        if (streak == need) { return i - need + 1; }   // where the streak started
    }
    else
    {
        streak = 0;
    }
}
return -1;

6. Search with early return

for (int i = 1; i <= n; i++)
{
    if ( /* item i is the one */ ) { return i; }
}
return -1;              // only after checking everything

Real mistake From the Recovery Check, pattern 3

slowest = i;      // ✗ slowest was compared as a time, then given an order number
if (i > most)     // ✗ compares the order number, not the time
return i;         // ✗ after the loop, i no longer exists

Picking the loop bounds

Things are numberedLoop
1 to n (orders, days, games)for (int i = 1; i <= n; i++)
0 to 59 (minutes)for (int m = 0; m <= 59; m++)
Characters of a Stringfor (int i = 0; i < s.length(); i++)
Pieces of length k in a Stringfor (int i = 0; i <= s.length() - k; i++)

Read the precondition. It tells you where the numbering starts and stops.

Show answer
public double averageScore(int numRounds)
{
    int total = 0;
    for (int r = 1; r <= numRounds; r++)
    {
        total += player.getScore(r);

    return (double) total / numRounds;

Write public int firstRoundAbove(int limit). It returns the first round from 1 to 20 with a score above limit, or −1.
Show answer
public int firstRoundAbove(int limit)
{
    for (int r = 1; r <= 20; r++)
    {
        if (player.getScore(r) > limit)
        {
            return r;
        }
    }

D5.4
Write public boolean hasHotStreak(int need). It returns true if the player scored 10 or more in need rounds in a row.
Show answer
public boolean hasHotStreak(int need)
{
    int streak = 0;
    for (int r = 1; r <= 20; r++)
    {
        if (player.getScore(r) >= 10)
        {
            streak++;
            if (streak == need)
            {
                return true;
            }
        }
        else
        {
            streak = 0;
        }
    }

}

Day 6: Timed practice and self-scoring

Today’s goal: two full FRQ 1 questions under exam time, scored the way AP readers score them. This is the work you photograph and upload.

How FRQ 1 is graded

Readers give a point for each piece of correct logic. You do not need perfect code to earn most of the points.

Usually not penalized

  • A missing semicolon or int when the meaning is clear
  • = instead of ==
  • Missing ( ) around a condition
  • Small spelling or capital-letter slips when it’s clear what you meant

Costs points

  • Calling a method on the wrong thing, or with the wrong arguments
  • Comparing the wrong values, or with < when the question needs >
  • Returning the wrong thing, too early, or not at all
  • Printing with System.out.println instead of returning
  • Not calling a method the question says you must use
Part (b) is graded on its own. Readers assume your part (a) works, even if you left it blank. Always do part (b).

The exam routine

  1. Read the whole question, including every example table. Underline what the method returns.
  2. Circle the methods you are given and the ones you must use.
  3. Read the preconditions. Don’t check what they already promise.
  4. Name the pattern (Day 5). Write 3–4 lines of pseudocode.
  5. Write the code. Copy object and method names exactly from the class information.
  6. Trace one example from the question through your code. Fix what doesn’t match.
  7. Cross out mistakes with one line instead of erasing. Crossed-out work isn’t graded, but it saves time.

Timed question 2: HikeTracker (22 minutes)

A new question, in our class format: part (a) is worth 4 points, part (b) 3 points.

public class HikeTracker
{
    private Hiker hiker;

    // Hiker has these methods:
    //   /** Returns the miles hiked on day d. Precondition: 1 <= d <= 30 */
    //   public double getMiles(int d)
    //   /** Returns the name of the trail hiked on day d. Precondition: 1 <= d <= 30 */
    //   public String getTrail(int d)

    /** Returns the length of the longest run of days in a row, from day 1 to
     *  day numDays, on which the hiker hiked at least goal miles.
     *  Precondition: 1 <= numDays <= 30 */
    public int longestRun(int numDays, double goal)
    { /* to be implemented in part (a) */ }

    /** Returns true if the hiker met the challenge in days 1 to numDays,
     *  as described in part (b). Precondition: 1 <= numDays <= 30 */
    public boolean metChallenge(int numDays)
    { /* to be implemented in part (b) */ }
}

Example data for one hiker:

Day1234567
getMiles(d)6.05.52.05.07.55.23.0
getTrail(d)"Lake Loop""River Trail""Eagle Peak""Lake Loop""Ridge Run""River Trail""Lake Loop"

(a) Write longestRun. With the data above, longestRun(7, 5.0) returns 3 (days 4, 5 and 6). longestRun(7, 6.0) returns 1. longestRun(2, 8.0) returns 0.

(b) Write metChallenge. The challenge is met if either the longest run of days with at least 5.0 miles is 3 or more, or the hiker hiked a trail whose name contains "Peak" on any of days 1 to numDays. You must call longestRun appropriately to receive full credit. With the data above, metChallenge(7) returns true, and metChallenge(2) returns false.

Show part (a) solution and rubric
public int longestRun(int numDays, double goal)
{
    int run = 0;
    int longest = 0;
    for (int d = 1; d <= numDays; d++)
    {
        if (hiker.getMiles(d) >= goal)
        {
            run++;
            if (run > longest)
            {
                longest = run;
            }
        }
        else
        {
            run = 0;
        }
    }
    return longest;
}
PointEarned when
1Loops days 1 to numDays and calls hiker.getMiles(d)
2Compares with >= goal and adds 1 to the run when the goal is met
3Resets the run to 0 when the goal is missed
4Keeps the longest run so far and returns it after the loop

Watch out: if you only update longest in the else, a run that lasts until the last day never gets counted.

Show part (b) solution and rubric
public boolean metChallenge(int numDays)
{
    if (longestRun(numDays, 5.0) >= 3)     // part (a) method: no dot
    {
        return true;
    }
    for (int d = 1; d <= numDays; d++)
    {
        if (hiker.getTrail(d).indexOf("Peak") >= 0)
        {
            return true;
        }
    }
    return false;                           // only after checking every day
}
PointEarned when
1Calls longestRun(numDays, 5.0) with no dot and checks for 3 or more
2Loops days 1 to numDays and checks hiker.getTrail(d).indexOf("Peak") against −1
3Returns true when either part is met, and false only after everything is checked

Common mistakes: hiker.longestRun(...) (longestRun belongs to HikeTracker), getTrail(d).equals("Peak") (the name only contains Peak), and return false inside the loop.

Brackets and conditions

  • Every call has (). Conditions go in ().
  • { goes after the ). else has no condition.
  • No ; after for (...) or if (...). Close the loop before return.
  • x >= 10 && x <= 20 · x == 3 || x == 5 · !(a && b) is !a || !b
